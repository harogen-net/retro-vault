# Plan

## 目的
- レトロゲームのパスワード画面を、アルバム単位で管理できるPWAを提供する
- iOSでの利用を主眼に、オフラインでも閲覧・編集できる構成にする

## プロダクト方針
- 1アルバム = 1ゲーム（または1管理単位）として運用する
- 1シーン（Photo）に対して、1枚以上の画像（PhotoImage）を保持する
- シーンごとにメモ（進行状況や補足）を保存・編集できる

## 技術スタック
- React 19
- TypeScript
- Vite
- Ionic
- IndexedDB
- vite-plugin-pwa

## データ保存方針
- 永続化ストレージは IndexedDB を使用する
- アプリ内部では画像データを Blob として保持する
- サムネイルは保存時に別Blobとして生成して保持する
- import/export のアーカイブでは JSON 内で画像を base64 化して扱う

## 主要機能
- アルバム一覧
- アルバム作成（撮影/選択画像から開始）
- アルバム詳細（サムネイル一覧）
- シーン詳細（拡大・パン・複数画像切替）
- シーンメモ編集
- 画像追加・画像削除
- 複数シーン選択、移動、削除
- アルバム名変更
- アルバム削除
- アルバム単位のエクスポート（ZIP）
- アルバム単位のインポート（ZIP）

## エクスポート/インポート仕様
- 形式: ZIP
- エクスポートファイル名: （アルバム名）.zip
- エントリ: album.json
- album.json にはメタ情報・アルバム・シーン・画像情報を含める
- 画像本体は base64 文字列として格納する
- 形式バージョンを持ち、対応外バージョンはエラーにする

## UI/UX方針
- モバイルファースト（iOS優先）
- オフラインでも主要操作を完結可能にする
- 画面遷移は「一覧 -> アルバム -> シーン」の3階層を基本にする

## PWA/配信運用仕様
- Service Worker はアプリ起動時に登録し、自動更新を有効化する
- 設定メニューに「アプリのリロード」を設け、手動で最新化を実行できる
- 手動リロード時は Service Worker 更新・待機中SWの切替要求・登録解除を順次試行する
- 手動リロード時は Cache Storage の既存キャッシュ削除を試行する
- リロード後にバージョン情報を表示できるよう、pending情報を一時保存して引き継ぐ
- 設定メニューに「バージョン情報」を設け、version/deploy/hash を表示する
- GitHub Pages 配信を想定し、ルーティングは Hash Router を採用する

## 実装・運用ルール
- ページ専用コンポーネントは src/pages/(domain) 配下に置く
- 再利用前提コンポーネントのみ src/components 配下に置く
- ページの状態遷移・副作用は hooks へ寄せる
- 画像処理は共通hook/ユーティリティで重複を避ける
